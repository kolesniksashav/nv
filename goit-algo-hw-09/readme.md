# hw-01 — Видача решти: жадібний алгоритм та динамічне програмування

## Опис завдання
Метою роботи було реалізувати два алгоритми для задачі видачі решти покупцеві за допомогою монет фіксованих номіналів [50, 25, 10, 5, 2, 1]:
- жадібний алгоритм, який завжди обирає найбільший можливий номінал;
- алгоритм динамічного програмування, який гарантує мінімальну кількість монет.

Також необхідно було порівняти ефективність обох підходів.

## Реалізація
Було реалізовано два підходи:
- `find_coins_greedy(amount)` — жадібний алгоритм, що завжди бере найбільшу доступну монету.
- `find_min_coins(amount)` — динамічне програмування, що знаходить мінімальну кількість монет.

### Жадібний алгоритм
Жадібний алгоритм послідовно використовує монети з найбільшим номіналом, зменшуючи залишок суми. Він працює швидко та просто, але не завжди гарантує оптимальний результат для довільних наборів монет.

### Алгоритм динамічного програмування
Алгоритм динамічного програмування обчислює мінімальну кількість монет для кожної суми від 1 до заданої. Він завжди знаходить оптимальне рішення, але має значно більшу часову складність.

## Коректність
Для набору монет [50, 25, 10, 5, 2, 1] жадібний алгоритм дає оптимальну відповідь, оскільки система монет є “канонічною” (greedy працює правильно).

## Порівняння ефективності
### Теоретична оцінка
- Greedy має складність O(k), де k — кількість номіналів. У нашому випадку k=6, тобто фактично O(1).
- DP має складність O(amount * k), тому при великих сумах значно повільніший, бо будує таблицю для всіх значень до amount.

### Емпіричні результати (заміри часу)
Порівняння швидкодії:
      Сума |   Greedy (s) |       DP (s)
----------------------------------------
       113 |     0.000002 |     0.000068
      1004 |     0.000003 |     0.000696
     10025 |     0.000002 |     0.007182
    100007 |     0.000001 |     0.074680

Зі збільшенням суми час виконання алгоритму динамічного програмування зростає майже лінійно, тоді як жадібний алгоритм має практично сталий час виконання. Це підтверджує теоретичні оцінки складності O(amount × k) для DP та O(k) для greedy.

## Практичний висновок
- Оскільки набір монет [50, 25, 10, 5, 2, 1] є канонічним, жадібний алгоритм завжди знаходить оптимальне рішення, тому в даній задачі його доцільно використовувати замість повільнішого DP.
- Для нестандартних наборів монет жадібний алгоритм може давати неоптимальні результати, у таких випадках доцільно застосовувати динамічне програмування.
