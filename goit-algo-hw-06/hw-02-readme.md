# Домашнє завдання hw-02 — DFS vs BFS для пошуку шляхів у графі

## Мета
1. Реалізувати **DFS** і **BFS** для знаходження шляхів у графі (завдання 6_1).
2. Порівняти отримані шляхи та пояснити різницю.

> У цьому завданні DFS/BFS знаходять шляхи в **неваговому сенсі** (оптимальність — за кількістю ребер).  
> Вага `weight` у ребрах тут **не використовується**. Для найкоротших шляхів з урахуванням ваг потрібен алгоритм Дейкстри.

---

## Реалізація (hw-02.py)

- `dfs_paths_tree(graph, start)` — ітеративний DFS на стеку:
  - повертає порядок обходу,
  - формує `parent` (DFS-дерево), за яким можна відновити **один** шлях `start -> v`.

- `bfs_paths_tree(graph, start)` — ітеративний BFS на черзі:
  - повертає порядок обходу,
  - формує `parent` (BFS-дерево), яке дає **найкоротший шлях за кількістю ребер**.

- `reconstruct_path(parent, start, goal)` — відновлює шлях `start -> goal` за `parent`.

Щоб результат був відтворюваним (однаковим між запусками), сусіди беруться через `sorted(...)`.

Використання `sorted(...)` для перебирання сусідів не впливає на коректність **BFS**. Воно лише фіксує порядок обходу, забезпечуючи детермінований результат. **BFS**, як і раніше, знаходить найкоротші шляхи за кількістю ребер, хоча конкретний маршрут може відрізнятися залежно від порядку сусідів.

Використання `sorted(...)` для перебирання сусідів не впливає на коректність алгоритму **DFS**. Воно лише фіксує порядок вибору наступної вершини, що призводить до детермінованого, але не єдиного можливого шляху обходу. **DFS** не гарантує найкоротший шлях, і зміна порядку сусідів змінює лише форму дерева пошуку, а не коректність алгоритму.
---

## Порівняння результатів

### BFS
- Обходить граф **рівнями**: спочатку всі вершини на відстані 1 ребро від `A`, потім 2, і т.д.
- Тому шлях, який відновлюється за `bfs_parent`, є **найкоротшим за кількістю ребер**.

### DFS
- “Занурюється” вглиб: бере сусіда, потім сусіда сусіда і т.д., поки може.
- Шлях залежить від **порядку сусідів** (у нас він стабілізований `sorted()`).
- DFS **не гарантує** найкоротший шлях.

---

## Чому шляхи відрізняються
- **BFS** оптимізує кількість ребер (мінімум кроків).
- **DFS** фіксує шлях у момент першого відвідування вершини — це шлях у DFS-дереві, не обов’язково мінімальний.

---

## Висновки
1. BFS корисний для пошуку **найкоротшого шляху в неваговому графі**.
2. DFS корисний для задач на структуру графа (компоненти зв’язності, досяжність тощо), але не для оптимального шляху.
3. Для вагових графів (як у нашому прикладі) “справжній” найкоротший шлях за вагою треба шукати алгоритмом Дейкстри.
