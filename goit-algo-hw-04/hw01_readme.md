# Порівняння алгоритмів сортування: вставки, злиття та Timsort

## Мета

Емпірично порівняти час виконання трьох алгоритмів сортування:

- сортування вставками (`insertion_sort`);
- сортування злиттям (`merge_sort`);
- вбудований алгоритм Python (`sorted`, Timsort).

## Умови експерименту

- Мова: Python 3.11
- Модуль для вимірювань: `timeit`
- Розміри масивів: `1000`, `5000`, `10000`
- Типи даних:
  - випадковий масив (`random`);
  - вже відсортований (`sorted`);
  - відсортований у зворотному порядку (`reversed`).
- Для кожної комбінації алгоритм–тип–розмір виконано N повторів (у мене N = 3), результат — середній час.

## Висновки

Основні висновки з експерименту
1. Insertion sort підтвердив квадратичну складність O(n²)

Це видно одразу:

size	random	reversed	sorted
1000	0.06 s	0.083 s   0.000251 s
5000	0.85 s	1.48 s    0.000886 s
10000	3.00 s	6.18 s    0.001932 s

Зростання часу виконання приблизно квадратичне — при збільшенні масиву у 10 разів (1000 → 10000) час зріс у 50–70 разів.
Причина: кожна вставка потребує зсуву елементів.

Особливо погано insertion sort працює для reversed (найгірший випадок).
Для sorted показує себе добре, бо майже не робить зсувів — O(n).

Висновок: Алгоритм непридатний для великих або невпорядкованих наборів.

2. Merge sort стабільний, передбачуваний і швидкий: O(n log n)

Дані:

size	random	reversed	sorted
1000	0.0041	0.0140	  0.0031
5000	0.0197	0.0133	  0.0135
10000	0.0436	0.0299	  0.0327

Ключові спостереження:
- час зростає приблизно логарифмічно разом зі збільшенням n;
- практично не залежить від упорядкованості вхідних даних;
- merge sort значно швидший за insertion sort у реальних масштабах.

Висновок: Merge sort добре масштабується та дає стабільні результати на будь-яких даних.

3. Timsort — абсолютний лідер у всіх тестах.
Теоретична складність O(n log n), O(n) на майже відсортованих.

Результати говорять самі за себе:

size	random	sorted	reversed
1000	0.000297	0.000019	0.000041
5000	0.000901	0.000086	0.000113
10000	0.001896	0.000230	0.000339

Факти:

3.1. Timsort у рази швидший, ніж merge sort:

Наприклад, на n = 10000:
Timsort: 0.0019 s
Merge sort: 0.0436 s

Результат: різниця в ≈ 23 рази

3.2. Timsort неймовірно швидкий на вже відсортованих даних

На n = 10000:
Timsort (sorted): 0.00023 s
Merge sort (sorted): 0.0327 s
Insertion sort (sorted): 0.00193 s

Висновок: Timsort використовує "runs" — підпослідовності, які вже впорядковані → O(n).

3.3. Timsort швидший за всі алгоритми навіть у найгіршому випадку

Навіть для reversed:

Timsort: 0.000339 s
Merge sort: 0.0299 s
Insertion sort: 6.177 s

## Головний висновок

Емпіричні результати підтверджують, що Timsort значно ефективніший за класичні алгоритми. Завдяки комбінації insertion sort та merge sort він працює швидше в усіх випадках і особливо ефективний на реальних даних, які часто містять локальні впорядковані підпослідовності. Саме тому Python використовує Timsort, а розробники у 99% випадків покладаються на sorted() замість власних реалізацій сортування.
